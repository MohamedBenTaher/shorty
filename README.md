# Shorty

A URL shortener built as a **system design experiment** — three approaches to ID generation, one codebase.

## The Experiment

Generating short, unique codes for URLs seems simple. But underneath lies a distributed systems challenge: how do you guarantee global uniqueness at scale without creating a bottleneck?

Shorty answers that question three different ways. Same REST API, same database, same frontend. The only variable is the ID generation strategy.

| Branch | Approach | How IDs are made |
|---|---|---|
| `main` | **Random Hash** | Cryptographically random 64-bit number → Base62 |
| `approach-2-unified-increment` | **Unified Increment** | PostgreSQL `nextval()` sequence → Base62 |
| `approach-3-distributed-increment` | **Distributed Snowflake** | Timestamp + shard ID + sequence → Base62 |

## Quick Start

```bash
git checkout main          # or any approach branch
docker compose up -d
./gradlew bootRun
```

Open `http://localhost:8080` — paste a URL, get a short link.

## API

```
POST /api/shorten          { "longUrl": "https://..." }
→   { "shortUrl": "...", "shortCode": "..." }

GET  /s/{shortCode}        → 302 redirect to original URL
```

## Architecture

```
Browser (HTML/JS) → Spring Boot REST API → PostgreSQL
                        ↑
                   ID Generator (varies by branch)
```

- **Backend:** Java 21, Spring Boot 3.4, Spring Data JDBC
- **Database:** PostgreSQL with `BIGINT GENERATED BY DEFAULT AS IDENTITY`
- **Frontend:** Zero-dependency HTML/CSS/JS served as static resources
- **Encoding:** Base62 `[0-9A-Za-z]` shared across all approaches

## The Three Approaches

### Approach 1 — Random Hash (`main`)

Generates a cryptographically random 64-bit number, encodes it to Base62. Stateless, coordination-free, unpredictable. Codes settle around 11 characters. Mathematically collision-resistant up to billions of entries.

**Best for:** Public URL shorteners where privacy and unpredictability matter.

### Approach 2 — Unified Increment (`approach-2-unified-increment`)

Asks PostgreSQL for the next value from a sequence (`SELECT nextval()`), encodes it to Base62. Atomic, guaranteed unique. Single-character codes for the first 62 URLs. The sequence is a single bottleneck at extreme scale.

**Best for:** Internal tools with modest volume where short codes are delightful.

### Approach 3 — Distributed Snowflake (`approach-3-distributed-increment`)

Each server generates globally unique 64-bit IDs by packing timestamp (42 bits), shard ID (10 bits), and sequence number (12 bits) into a single integer. Zero coordination between servers. ~4 million IDs/sec per worker, up to 1,024 workers.

**Best for:** Multi-region, high-throughput platforms that need to scale horizontally.
